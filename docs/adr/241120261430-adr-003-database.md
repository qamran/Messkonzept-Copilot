# Architecture Decision Record (ADR) 003: Supabase Postgres and Storage instead of SQLite

- **Status:** accepted
- **Date:** 24.11.2026
- **Design reference:** design doc sections 7 and 13

## Context

The brief suggests "SQLite or JSON files for saved state". Our harness state (runs, checkpoints, approvals) and our valuable data (approved catalogue, user-verified gold data, the rule table) must survive restarts and the loss of the single Oracle VM.

We also need a private place for cached operator PDFs and rendered diagram images (never in the public repo), and a vector store for RAG.

## Options considered

| Option | Pros | Cons |
|---|---|---|
| SQLite on a PersistentVolume | Simplest; what the brief names | Data is lost if the node dies; a single replica; no vector search built in |
| Self-hosted Postgres in k3s | Full control | Backups, upgrades and storage on a free VM are ours to run |
| **Supabase (free tier): Postgres + Storage + pgvector** | Managed Postgres off the cluster; Storage for files; pgvector for RAG; free | 500 MB database, 1 GB storage, 5 GB egress/month, **no automatic backups**, pauses after 1 week of inactivity |

## Decision

**Supabase free tier:**
- **Postgres** for runs, checkpoints, approvals, the catalogue, gold data, the rule table and RAG chunks (pgvector plus German full-text search).
- **A private Storage bucket** for cached PDFs and renders.
- **Clerk stays the only login.** The backend uses a server-side Supabase key that is never sent to the frontend.

## Consequences

- **Size rules:**
  - Checkpoints store deltas and references, and step detail of finished runs is pruned.
  - Renders are cached by content key.
  - The backend keeps a local render cache.
  - Evaluations and CI use Postgres in Docker, never Supabase.
- **Backups (the free tier has none):**
  - A nightly CronJob runs `pg_dump` to Oracle Object Storage, with 14 days of retention.
  - **One documented restore drill** (restore into a throwaway Postgres, check row counts, record the steps and timing in the runbook). An automated monthly restore test is deferred (design doc section 20, item 82). *Revised 24.11.2026 after independent review.*
  - The catalogue and gold data can also be exported as JSON.
- **Pausing:** accepted by the user. Wake the project before demos and the review.
- **Migrations** use SQLAlchemy + Alembic, the same locally, in CI and in production.
- **Upgrade path:** Supabase Pro (8 GB, daily backups) if the limits are reached.
