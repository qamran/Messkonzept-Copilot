## Design choices

- **API Deployment:** `replicas` from values (default 1). HTTP probes on `/health` (startup, readiness, liveness). Resource requests and limits from values.
- **Worker Deployment:**
  - `replicas: 1` written in the template, not a value: the design has one worker with a Postgres lease (decision 26).
  - `strategy: Recreate`: the old pod stops before the new one starts, so two workers never run at once. The lease (MKC-20) is the real guard; this keeps upgrades simple.
  - `terminationGracePeriodSeconds: 300` (see below), `command: ["mkc-worker"]`.
  - Probes: the worker has no HTTP port. It touches a heartbeat file in `/tmp` on every poll. An exec probe runs `mkc-worker-health`, which exits 0 only if the file is younger than a limit. Without a probe the pod would show Ready even while it crash-loops.
- **Grace period (decision 42):** a turn is one model call plus its tool calls, then a checkpoint (design doc section 8). Budget:
  - model call timeout: 180 s (the `ModelClient` timeout in later tickets must stay at or below this)
  - tool calls in the turn: 60 s
  - checkpoint and lease release: 30 s
  - margin: 30 s
  - total: **300 s**. MKC-10's `helm upgrade --timeout` must be longer than this.
- **Pod security:** `runAsNonRoot`, uid/gid 10001 (as in the image), `allowPrivilegeEscalation: false`, drop all capabilities, `readOnlyRootFilesystem` with an `emptyDir` on `/tmp`, seccomp `RuntimeDefault`, `automountServiceAccountToken: false`.
- **Service:** ClusterIP, port 80 → the API's 8000.
- **Ingress:** `ingressClassName` from values (k3s ships Traefik). TLS through cert-manager: the annotation `cert-manager.io/cluster-issuer` and `tls.secretName` from values. The chart does not create a `Certificate` or `ClusterIssuer` (kind has no cert-manager CRDs; MKC-10 installs cert-manager on k3s).
- **Secrets:** `secrets:` in values is a map that becomes a Secret, loaded into both pods with `envFrom`. `existingSecret` uses a Secret created outside the chart instead (production, MKC-10). `values.yaml` holds no secret values. A checksum annotation restarts the pods when the Secret changes.
- **Non-secret settings:** `env:` in values (for example `MKC_CLERK_ISSUER`, `MKC_CORS_ORIGINS`).
- **Image:** `image.repository` (default `ghcr.io/qamran/messkonzept-copilot-backend`) and `image.tag` (required; no `latest`).
- **No database in the kind test:** `/health`, `/api/version` and the worker do not touch the database yet. The test values set a placeholder `DATABASE_URL`. Migrations as a Helm hook come with the deploy (MKC-10) or the first table that needs them.

## Tests

- `scripts/check_helm.py` (stdlib only; runs in the `docs` job without Helm), red first: the chart files exist; the worker has `replicas: 1`, `Recreate`, a numeric grace period of at least 300 and an exec probe; both Deployments have probes and resources; the Ingress has the cert-manager annotation and TLS; `values.yaml` has no secret values and no `latest` tag.
- `scripts/kind_smoke.sh` (local and CI), red first (no chart yet):
  - its own cluster name and a temporary `KUBECONFIG`, so `~/.kube/config` is never touched; the cluster is deleted at the end
  - builds `mkc-backend:kind` with `MKC_COMMIT`, `kind load`, `helm install --wait` with `deploy/helm/mkc/ci-values.yaml` (Ingress on, TLS on, placeholder Secret)
  - `/health` 200 and `/api/version` returns the commit, through the Service (port-forward)
  - the worker pod is Ready with 0 restarts after a short wait
  - deleting the worker pod logs `signal SIGTERM received` and `worker stopped`
  - on failure: `describe`, events and logs before the cleanup
- CI job `kind`: `helm lint --strict` (default and CI values), `helm template`, then the smoke script.
